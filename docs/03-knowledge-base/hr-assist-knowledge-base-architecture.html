The decision at each source type, side by side

What's actually being decided for each category, and why it was resolved the way it was.

Access-level fix

SharePoint — declined access

Problem: personal access request to a restricted site was denied.

Fix: the connector only needs an app-level permission grant from the site owner/IT — not the builder's personal membership. Re-ask framed as "authorize the Quick connector," not "add me."

Blocked — Option A

ebscochoice.com — Web Crawler

Problem: site's bot protection returns HTTP 403 to all seed URLs.

Fix (if pursued later): identify who actually runs the site (internal vs. vendor), ask them to allowlist a specific, unique crawler User-Agent string — not a broad IP range.

Chosen — Option B

ebscochoice.com — Manual upload

Decision: download the specific known PDFs from the spreadsheet and upload them directly into the Space.

Why: low document count, project is in an intentionally simple early phase, avoids depending on an external party's security team's timeline.

Needs HR action

Personal OneDrive tribal knowledge

Problem: answers exist only in one person's personal OneDrive doc — fragile and unofficial.

Fix: HR writes these up properly into a real, shared SharePoint library first; only then does it get indexed like any other SharePoint source.

The one thing worth emphasizing to stakeholders

Security enforcement happens per employee, every time — not once, at setup.

Indexing ≠ access

A document being indexed (searchable by the agent at all) is a one-time, admin-level step. Whether a specific employee can actually see that document's content in an answer is checked fresh, every single question, against that employee's own real SharePoint permissions.

No bypass, for anyone

Even the person who built the agent and configured every connector gets filtered out of content they personally don't have SharePoint access to. Admin/builder status on Quick has no bearing on SharePoint-level permissions — they're separate systems that only intersect through this per-query check.
